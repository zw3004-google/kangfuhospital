# 业务数据字典

## 1. 通用约定

| 项目 | 基线 |
|---|---|
| 一次住院唯一键 | `inpatient_no + admission_times`（已确认） |
| 字符集 | UTF-8（已确认） |
| 业务时区 | `Asia/Shanghai`（已确认） |
| 日期 | 仅自然日时使用 `date`/`LocalDate` |
| 精确时间 | 数据库使用 `timestamptz`，应用按上海时区展示 |
| 金额 | `numeric(16,2)`，禁止二进制浮点计算 |
| 系数 | `numeric(10,4)` |
| 金额舍入 | 计算过程保持高精度，最终金额四舍五入至 2 位（已确认） |
| 主业务删除 | 欠费和预出院不物理删除、不作废；营养/居家预约逻辑删除 |

## 2. 患者与住院 `patient_encounter`

| 业务字段 | 代码/数据库字段 | 类型 | 必填 | 来源与规则 | 重复导入 |
|---|---|---:|:---:|---|---|
| 住院号 | `inpatient_no` | varchar(64) | 是 | 医院源数据；唯一键之一 | 定位记录，不覆盖为空 |
| 住院次数 | `admission_times` | integer | 是 | 正整数；唯一键之一 | 定位记录，不允许修改键值 |
| 患者姓名 | `patient_name` | varchar(128) | 是 | 源数据 | 覆盖 |
| 所属科室 | `department_id` | bigint | 是* | 通过科室编码匹配内部 ID；*正式模板需提供科室编码 | 覆盖，转科更新原记录 |
| 住院病区 | `ward_name` | varchar(128) | 否 | 源数据 | 覆盖 |
| 费别 | `fee_type` | varchar(64) | 是 | 导入仅按费别名称匹配当前启用系数；模板不要求费别编码 | 覆盖 |
| 主管医生工号原文 | `doctor_employee_no_source`（待迁移） | varchar(64) | 是* | 按工号精确匹配；*正式导入应必填 | 覆盖 |
| 主管医生姓名原文 | `doctor_name_source` | varchar(128) | 否 | 仅用于展示、核对和审计，不参与关联 | 覆盖 |
| 主管医生用户 | `doctor_user_id` | bigint | 否 | 工号精确匹配到唯一启用用户后的用户 ID | 重新匹配后覆盖 |
| 医生匹配状态 | `doctor_match_status` | enum | 是 | `MATCHED/NOT_FOUND/AMBIGUOUS/PENDING` | 重算 |
| 入区/入院时间 | `admitted_at` | timestamptz | 否* | 源数据；*排序和统计依赖，模板应要求 | 覆盖 |
| 实际出院时间 | `discharged_at` | timestamptz | 否 | 源数据；清空后重新按在院处理 | 覆盖 |
| 源数据更新时间 | `source_updated_at` | timestamptz | 是 | 每次成功获取/导入时间 | 更新 |

科室匹配建议使用稳定的 `department_code`，名称只用于展示。正式源系统科室编码和转科历史口径仍需信息科提供。

## 3. 欠费记录 `arrears_record`

| 业务字段 | 代码/数据库字段 | 类型 | 来源/计算 | 重复导入 |
|---|---|---:|---|---|
| 欠费类型 | `arrears_type` | varchar(64) | 源数据 | 覆盖 |
| 总费用 | `total_cost` | numeric(16,2) | 源数据 | 覆盖 |
| 预交金 | `prepaid_amount` | numeric(16,2) | 源数据 | 覆盖 |
| 医保支付 | `medical_insurance_paid` | numeric(16,2) | 源数据 | 覆盖 |
| 个人账户支付 | `personal_account_paid` | numeric(16,2) | 源数据 | 覆盖 |
| 原始应交押金 | `original_required_deposit` | numeric(16,2) | 源数据 | 覆盖 |
| 系数快照 | `coefficient_snapshot` | numeric(10,4) | 导入时当前启用系数 | 覆盖源数据时重新取当前系数并固化 |
| 系数版本 | `coefficient_version_id` | bigint | 按费别名称匹配到的启用版本 | 覆盖源数据时重新匹配并固化，用于审计追溯 |
| 最终应交押金 | `final_required_deposit` | numeric(16,2) | 原始应交押金 × 系数快照 | 重算 |
| 押金差额 | `deposit_difference` | numeric(16,2) | 预交金 − 最终应交押金 | 重算，可正/零/负 |
| 是否欠费 | `in_arrears` | boolean | 押金差额 `< 0` | 重算 |
| 欠费金额 | `arrears_amount` | numeric(16,2) | 欠费时为押金差额绝对值，否则为 0 | 重算 |
| 缴费状态 | `payment_status` | enum | `UNPAID/PAID`，人工维护 | 保留 |
| 欠费原因 | `arrears_reason` | text | 人工维护 | 保留 |
| 追缴进度 | `recovery_progress` | text | 人工维护 | 保留 |
| 最近操作人 | `last_operated_by` | bigint | 系统记录 | 导入不覆盖 |

当前欠费统计范围：`in_arrears = true AND payment_status <> 'PAID'`。

## 4. 预出院记录 `discharge_record`

| 业务字段 | 代码/数据库字段 | 类型 | 规则 |
|---|---|---:|---|
| 预计出院时间 | `planned_discharge_at` | timestamptz | 主管医生填报；实际出院后不可编辑 |
| 预计时间最后修改时间 | `planned_discharge_updated_at` | timestamptz | 用于 12 小时异常判断 |
| 实际出院时间 | `actual_discharge_at` | timestamptz | 源数据；为空时按在院处理 |
| 异常编码 | `abnormal_codes` | text/集合 | `LATE_PLAN/MISSING_PLAN/DATE_MISMATCH`，可同时存在 |
| 异常原因 | `abnormal_reason` | text | 系统判定异常时由主管医生填写 |
| 特殊患者 | `special_patient` | boolean | 为是时特殊原因必填，其余后续填报项置灰 |
| 特殊原因 | `special_reason` | text | 特殊患者必填 |
| 是否需要随访 | `follow_up_required` | boolean | 随访员维护；否时 30/60 天项不可编辑 |
| 7/30/60 天随访 | `follow_up_day7/30/60` | text | 按实际出院后天数提醒，不限制实际填报时间 |
| 复诊预约 | `outpatient_appointment_at` | timestamptz | 门诊部负责填报 |

营养会诊和居家康复为一对多预约记录，修改或逻辑删除后须联动取消未发送提醒、重算统计并记录审计。

## 5. 用户、角色、科室

| 对象 | 关键字段 | 基线 |
|---|---|---|
| 用户 | `login_name` | 姓名拼音；重名顺序加数字（拼音库和编号格式待确认） |
| 用户 | `display_name` | 姓名 |
| 用户 | `employee_no`（待迁移） | 医院工号，正式关联键；建议全局唯一且必填，匹配时仅接受启用用户 |
| 用户 | `wecom_user_id` | 企微接收人唯一标识；正式导入是否必填待确认 |
| 用户 | `department_id` | 一个用户当前所属科室；跨科室角色范围由角色科室表配置 |
| 角色 | `role_code` | 稳定编码，不使用中文参与程序判断 |
| 用户角色 | `sys_user_role` | 一个用户可拥有多个角色；新建/导入后角色为空 |
| 科室 | `department_code` | 稳定外部匹配键，需信息科提供正式编码 |
| 科室 | `enabled` | 停用后不可用于新增匹配，历史数据保留 |

## 6. 空值和非法值

- 唯一键、患者姓名、费别等必填字段缺失：该行失败。
- 金额格式错误、住院次数非正整数、时间无法解析：该行失败。
- 主管医生工号找不到启用用户：导入可成功，但标记 `NOT_FOUND` 且不发送医生提醒。
- 工号重复属于用户主数据错误，应阻止用户导入/保存；存量异常未清理前患者匹配标记 `AMBIGUOUS`。
- 科室无法匹配：整行失败，不进入“未分配科室”（已确认）。
- 空白源字段表示未提供，不清空已有值；只有显式清空操作才清除（已确认）。
