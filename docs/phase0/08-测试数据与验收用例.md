# 测试数据与验收用例

## 1. 最低测试数据集

测试数据必须脱敏，不得复制真实患者身份证号、手机号或真实企微 Secret。

### 1.1 组织和账号

- 至少 3 个科室：A、B、停用科室 C。
- 至少 2 名主管医生，分别属于 A、B。
- 另设 2 名同名但工号不同的启用医生，用于验证系统不按姓名误匹配。
- 准备一个不存在的医生工号；通过存量异常数据模拟重复工号冲突（正常用户导入应直接拒绝重复工号）。
- 每个内置角色至少 1 个启用测试账号。
- 另设无角色用户、停用用户、无企微 ID 用户和锁定用户。
- 科主任角色至少配置 A 科室；另设一个配置 A+B 的多科室角色实例。

### 1.2 患者住院数据

- 同一住院号、不同住院次数的两次住院。
- 跨科室患者各 2 条，跨主管医生患者各 2 条。
- 医生工号唯一匹配、工号未匹配、重复工号冲突各 1 条。
- 在院、实际出院、实际出院时间被清空各 1 条。
- 预计与实际同日、不同日、缺少预计时间、12 小时内填报各 1 条。
- 有/无营养、居家、复诊预约，以及同一次住院多条预约。
- 随访需要、无需继续随访各 1 条。

### 1.3 欠费边界数据

- 押金差额为负、零、正各 1 条。
- 已缴费但差额为负 1 条。
- 三种欠费类型各 1 条。
- 系数为整数和小数的费别；无启用系数费别 1 条。
- 重复导入时包含人工欠费原因、追缴进度和已缴费状态的记录。

## 2. P0 验收用例

### 2.1 唯一键与覆盖

| 编号 | 场景 | 预期结果 |
|---|---|---|
| P0-01 | 相同住院号、不同住院次数 | 生成两次独立住院，不串数据 |
| P0-02 | 相同唯一键重复导入且患者改名/转科 | 更新原记录，不新增；数据范围同步变化 |
| P0-03 | 重复导入前已有欠费原因、追缴进度、已缴费 | 人工字段保持不变 |
| P0-04 | 文件内同一唯一键出现两行 | 整批失败并准确指出两行 |
| P0-05 | 导入中任一行业务校验失败 | 整批回滚，不产生半批数据 |

### 2.2 金额与报表

| 编号 | 场景 | 预期结果 |
|---|---|---|
| P0-06 | 原始押金 1000，系数 1.2，预交 900 | 最终押金 1200，差额 -300，欠费金额 300 |
| P0-07 | 预交等于或大于最终押金 | 差额为 0 或正，是否欠费为否，欠费金额 0 |
| P0-08 | 欠费患者标记已缴费 | 保留记录，但从人数、合计、排名和推送移除 |
| P0-09 | 修改启用费别系数 | 历史结果不追溯变化，新导入使用新版本 |
| P0-10 | 最新导入失败 | 报表仍显示上一成功批次和截至时间 |

### 2.3 权限

| 编号 | 场景 | 预期结果 |
|---|---|---|
| P0-11 | 科主任查询、导出、修改其他科室记录 | 均被拒绝 |
| P0-12 | 主管医生查询、导出、修改其他医生患者 | 均被拒绝 |
| P0-13 | 无导入权限用户直接调用导入 API | 403 |
| P0-14 | 无推送权限用户直接调用重发 API | 403 |
| P0-15 | 多角色用户 | 权限和数据范围按确认的合并规则生效 |
| P0-16 | 越权修改不存在/不在范围的 ID | 不更新任何行，不返回成功 |
| P0-16A | 两名医生同名但工号不同 | 按工号关联正确用户，不发生同名串联 |
| P0-16B | 医生工号不存在或用户已停用 | 导入成功并标记未匹配，不发送主管医生提醒 |

### 2.4 预出院和统计

| 编号 | 场景 | 预期结果 |
|---|---|---|
| P0-17 | 在院患者未填预计时间 | 显示未填报，但不判异常 |
| P0-18 | 实际出院且预计时间为空 | `MISSING_PLAN`，计入非计划出院 |
| P0-19 | 预计和实际日期不同 | `DATE_MISMATCH`，可与其他异常并存 |
| P0-20 | 实际出院后修改预计时间 | 被拒绝；其他允许字段仍可修改 |
| P0-21 | 4 人出院，2 人非计划 | 非计划出院率 50.00% |
| P0-22 | 同一住院有两条营养预约 | 营养预约人数只计 1 |
| P0-23 | 分母为 0 | 比率显示“—”，趋势点为空 |
| P0-24 | 删除预约 | 逻辑删除、取消未发送提醒、统计重算、审计完整 |

### 2.5 推送、安全和审计

| 编号 | 场景 | 预期结果 |
|---|---|---|
| P0-25 | 08:00 任务与即时任务并发 | 唯一键确保只存在一个主任务 |
| P0-26 | 企业微信连续失败 | 按 1/5/15 分钟重试，最终失败后可人工重发 |
| P0-27 | 接收角色无启用用户/医生未匹配 | 明确失败原因，不误发他人 |
| P0-28 | 推送内容 | 姓名脱敏，不含密码、Secret、token 和高敏信息 |
| P0-29 | 修改、导入、导出、推送、权限配置 | 记录操作人、时间、IP、业务键和前后值/结果 |
| P0-30 | 修改密码 | 首次强改；连续 5 次失败锁定 15 分钟；改密后其他会话失效 |

## 3. 非功能验收基线

| 项目 | 基线 |
|---|---|
| 并发用户 | 不超过 100 |
| 普通接口 P95 | ≤3 秒 |
| 复杂报表 P95 | ≤8 秒 |
| 1000 条导入 | ≤60 秒 |
| 小数据导出 | ≤30 秒；大数据后台生成 |
| 可用性 | 单机部署，计划维护除外 ≥99.5% |
| RPO | ≤1 小时 |
| RTO | 4～8 小时 |
| 浏览器 | Chrome/Edge 最近两个稳定版本 |
| 传输 | 全站 HTTPS |

性能验收必须记录服务器配置、数据库数据量、并发模型、预热方式和 P95 计算方式。

## 4. 验收证据

每个用例应保存：执行版本、环境、前置数据、操作步骤、请求/响应或截图、数据库核对结果、审计记录、执行人、日期和结论。自动化用例应进入版本库并能在空 PostgreSQL 环境重复执行。
