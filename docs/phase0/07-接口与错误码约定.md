# 接口与错误码约定

## 1. 通用协议

- API 前缀：`/api`。
- 业务 JSON 使用 UTF-8 和 `application/json`。
- 时间字段使用 ISO-8601，并携带偏移量，例如 `2026-08-31T08:00:00+08:00`。
- 金额在 JSON 中使用十进制数；前后端不得用浮点误差参与财务判断。
- 写操作应支持防重复提交；导入和推送任务使用业务唯一键保证幂等。

统一成功结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

统一失败结构建议：

```json
{
  "code": "VALIDATION_ERROR",
  "message": "请求参数校验失败",
  "data": null,
  "traceId": "...",
  "errors": [{"field": "admissionTimes", "message": "必须为正整数"}]
}
```

## 2. HTTP 状态与业务错误

| HTTP | 业务错误码示例 | 使用场景 |
|---:|---|---|
| 400 | `BAD_REQUEST` | JSON、日期、枚举或分页参数格式错误 |
| 401 | `UNAUTHENTICATED`、`SESSION_EXPIRED` | 未登录、凭证失效、会话超时 |
| 403 | `ACCESS_DENIED` | 无菜单、操作或数据范围权限 |
| 404 | `RESOURCE_NOT_FOUND` | 资源不存在 |
| 409 | `DUPLICATE_RESOURCE`、`BATCH_IN_PROGRESS`、`STATE_CONFLICT` | 唯一键冲突、批次占用、状态不允许 |
| 413 | `FILE_TOO_LARGE` | 文件超过限制 |
| 415 | `UNSUPPORTED_FILE_TYPE` | 非允许文件格式 |
| 422 | `VALIDATION_ERROR`、`IMPORT_VALIDATION_FAILED` | 可解析但不满足业务规则 |
| 429 | `TOO_MANY_REQUESTS` | 登录或接口限流 |
| 500 | `INTERNAL_ERROR` | 未预期异常，响应不得暴露堆栈或密钥 |
| 503 | `EXTERNAL_SERVICE_UNAVAILABLE` | 企业微信等外部服务不可用 |

## 3. 分页、筛选和排序

请求参数：

```text
page      从 1 开始
pageSize  允许 20、50、100、200；默认 50
sort      预定义字段编码，不接受任意 SQL 字段
order     asc/desc
```

分页响应：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 50
}
```

默认排序：欠费按入区时间倒序；预计出院按入院时间倒序。列表、导出和统计应复用同一筛选对象和数据范围。

## 4. 导入与导出

- 导入使用 `multipart/form-data`，字段名 `file`。
- 校验失败建议返回 422，响应包含批次号、汇总和错误报告下载标识。
- 正在处理同业务批次时返回 409 `BATCH_IN_PROGRESS`。
- 小数据导出同步返回文件；大数据使用后台任务并返回任务 ID。
- 导出文件名应包含业务、时间范围和生成时间。
- 导出必须使用当前用户数据范围，记录审计，并防止 CSV 公式注入。

| 方法 | 路径 | 用途 | 主要权限/范围 |
|---|---|---|---|

| GET | `/api/arrears/records/export` | 欠费导出 | DataScope；导出权限 |

| GET | `/api/audit/logs` | 操作历史 | 访问范围需统一 |

## 6. 接口验收原则

- 前端隐藏按钮不替代后端鉴权。
- 所有修改接口必须在写 SQL 中应用 DataScope。
- 未授权导出与直接访问接口必须返回 403。
- 401 前端清除会话并跳转登录；403 展示无权限页面且不退出登录。
- 生产响应和日志均不得包含密码、Secret、access token 或完整敏感患者信息。
