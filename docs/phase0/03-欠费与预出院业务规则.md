# 欠费与预出院业务规则

## 1. 欠费管理

### 1.1 金额计算

```text
最终应交押金 = 原始应交押金 × 导入时当前启用的费别系数
押金差额 = 预交金 − 最终应交押金
是否欠费 = 押金差额 < 0
欠费金额 = 是否欠费 ? abs(押金差额) : 0
```

- 押金差额必须展示真实的正、零或负值。
- 三种欠费类型使用同一计算方式。
- 系数与计算结果在导入时固化；系数调整不追溯重算历史数据。
- 同一费别同一时间只能有一个启用版本；启用版本不可修改，调整时新增版本并停用旧版本。
- 费别一旦被业务引用不得删除。
- 计算过程保持高精度，最终金额四舍五入至 2 位（已确认）。

### 1.2 当前欠费范围

只有同时满足以下条件的记录参与欠费人数、欠费合计、科室排名和推送：

```text
押金差额 < 0 AND 缴费状态 != 已缴费
```

- “已缴费”由业务人员人工标记，重复导入不得覆盖。
- 已缴费记录保留历史，不参与当前报表。
- 患者转为出院或结算状态变化时，欠费原因和追缴进度继续保留。
- 科室排名按患者当前所属科室的当前欠费金额合计降序；Top3 为全院科室前三名。

### 1.3 报表批次一致性

```text
全量校验 → 批量写入 → 批次成功 → 提交事务
→ 异步刷新统计 → 报表切换到最新成功批次
```

- 报表显示数据截至时间、最新成功批次号和汇总状态。
- 最新导入失败时继续展示上一次成功批次，禁止展示半批数据。
- 人工保存后重新计算相关患者和当月指标。

## 2. 预出院管理

### 2.1 状态和临近标签

- 未填报：预计出院时间为空。
- 已填报：预计出院时间非空。
- 临近出院不是独立状态；当前时间距预计出院时间不足 3 天时展示“临近”标签。
- 实际出院：实际出院时间非空。
- 实际出院时间清空后重新按在院患者处理。

### 2.2 异常规则

只对实际出院患者判断异常，异常编码可以同时存在：

| 编码 | 条件 |
|---|---|
| `LATE_PLAN` | 预计出院时间最后修改时间处于“实际出院日期次日 00:00”前 12 小时内 |
| `MISSING_PLAN` | 实际已出院但未填写预计出院时间 |
| `DATE_MISMATCH` | 预计出院日期与实际出院日期不一致 |

- 修改预计出院时间后重算异常。
- 异常由系统判断并只读展示；命中异常时异常原因必填。
- 多个异常同时命中时全部展示。
- 未填写预计出院时间的患者暂不发送非计划出院提醒。
- 患者实际出院后，预计出院时间不可再编辑，其余有权限字段仍可编辑。

### 2.3 特殊患者

- 选择“是”后特殊原因必填。
- 特殊原因下方的其余填报项置灰，不允许填写。
- 从“是”改为“否”时，原先被置灰字段保留历史值，但不参与当前流程和统计（已确认）。

### 2.4 会诊、康复和复诊预约

- 门诊部负责复诊预约，营养科负责营养会诊，居家康复科负责居家康复预约。
- 营养和居家预约为一对多，不受原型“最多 10 条”限制，使用分页或折叠展示。
- 预约时间不得设置为过去。
- 营养和居家预约允许修改、逻辑删除，不物理删除。
- 删除后取消未发送提醒，保留已发送记录，立即重算指标并记录原值、操作人和时间。

### 2.5 随访

- 出院后的第二天记为出院第 1 天。
- 在第 7、30、60 天上午 08:00 提醒随访员；系统不限制实际填报时间。
- 完成第 7 天随访后选择“无需回访”，第 30、60 天随访项置灰且不可填写。
- 实际出院时间清空时，取消未发送的 7/30/60 天提醒，保留历史发送记录。
- 一期不计算回访率。

## 3. 编辑和历史

- 第一期所有登录用户都能编辑其数据范围内可见患者；不要求填写修改原因。
- 修改前后值、操作人、时间和客户端 IP 必须进入审计日志。
- 欠费和预出院主记录不允许删除或作废。
- 患者取消住院或再次住院时，按在院逻辑重算；同一次住院仍由唯一键定位。
