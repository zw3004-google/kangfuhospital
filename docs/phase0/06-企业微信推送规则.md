# 企业微信推送规则

## 1. 配置与安全

- 使用企业微信自建应用，仅支持企微推送。
- Corp ID 和 Agent ID 已由需求材料提供，但文档不重复写入敏感配置；Secret 必须通过环境变量或服务器密钥文件注入。
- 接收人通过 `wecom_user_id` 匹配。
- Secret 禁止写入代码、数据库明文、日志和版本库。
- 消息链接指向医院内网，外网无法访问详情。

上线前待提供：测试 Secret、测试接收人、企微 API 出口/代理、DNS、证书和应用可见范围。

## 2. 消息隐私

- 患者信息使用“住院号 + 住院次数 + 脱敏姓名”。
- 不发送身份证号、手机号等高敏字段。
- 查看详情必须登录院内系统并再次执行数据权限校验。
- 推送记录和发送尝试日志不得记录 Secret 或 access token。

脱敏姓名格式建议：两字姓名显示“张*”，三字及以上显示“张**”；最终格式待医院确认。

## 3. 欠费通报

- 自动发送：每天 08:00，节假日照常；该口径于 2026-09-01 通报报表原型对齐时更新。
- 内容：所有当前欠费科室、欠费金额、各欠费类型金额和系统内网链接。
- 当前欠费范围：押金差额小于 0 且未标记已缴费。
- 接收人为科主任、主管医生等按角色和数据范围生成；具体每类接收内容需要在消息模板验收时确认。

## 4. 预出院提醒

| 类型 | 触发时间 | 接收人 | 基线内容 |
|---|---|---|---|
| 7/30/60 天随访 | 对应日期 08:00 | 所有启用的随访员角色用户 | “***患者今日需要随访。” |
| 居家康复 | 预约当天 08:00；当天 08:00 后新增/改到当天则即时 | 居家康复角色用户 | “***患者今日需要居家康复会诊。” |
| 营养会诊 | 预约当天 08:00；当天 08:00 后新增/改到当天则即时 | 营养科角色用户 | “***患者今日需要营养会诊。” |
| 非计划出院 | 出院后第 1 天 08:00 | 患者唯一匹配的主管医生 | “***患者非计划出院，请写明原因。” |

- 多位患者按行合并展示。
- 缺少预计出院时间的患者暂不发送非计划出院提醒。
- 接收角色没有启用用户、企微 ID 为空或主管医生无法唯一匹配时，直接失败并展示明确原因。

## 5. 即时任务与防重

当天 08:00 后新增或改到当天的预约，在保存成功后创建即时提醒。08:00 定时任务和即时任务必须使用相同唯一键抢占：

```text
提醒类型 + 住院号 + 住院次数 + 业务记录ID + 提醒日期
```

- 创建成功才发送；唯一键已存在则跳过。
- 原任务失败时沿用原任务重试，不创建第二个主任务。
- 预约删除或改到未来时取消尚未发送的当天任务。
- 同一患者当天多条相同类型预约是否合并，与“业务记录 ID”唯一键存在口径冲突。建议显示层合并、任务层按预约记录防重，需业务确认。

## 6. 状态与重试

建议状态：`PENDING`、`SENDING`、`RETRYING`、`SENT`、`FAILED`、`CANCELLED`。

- 初次失败后分别于 1、5、15 分钟后重试。
- 三次重试均失败后标记 `FAILED`，允许人工重发。
- `RETRYING` 状态时重发按钮不可用。
- 批量重发仅处理失败且当前仍可发送的记录。
- 人工重发不生成新的任务主记录，只追加发送尝试。
- 重发时消息内容使用当前患者数据。

推送任务和尝试明细关系：

```text
push_task（一条业务提醒）
  ├─ push_attempt（首次发送）
  ├─ push_attempt（自动重试）
  └─ push_attempt（人工重发）
```

每次尝试保存：尝试序号、触发方式、计划/实际时间、接收人、结果、企微错误码和脱敏后的错误信息。

## 7. 变更联动

- 预约逻辑删除：取消未发送任务，保留已发送历史。
- 实际出院时间清空：取消未发送的随访和非计划出院任务。
- 预约从今天改到未来：取消今天未发送任务，并为新日期建立任务。
- 患者、医生或接收角色变化：未发送任务发送时重新解析接收人；已发送历史不改变。
