## 1. 调整范围与确认结论

本计划用于补齐当前欠费明细页面与原型之间的差异。已确认：

1. 导出同时支持 Excel（`.xlsx`）和 CSV（`.csv`），两种格式使用相同筛选、权限、字段、顺序和数据范围。
2. 不恢复原型页面底部的业务说明文字。
3. 其余统计、筛选、字段、状态、编辑、历史、导入反馈和测试项按本计划实施。

## 2. 后端数据模型与查询

### 2.1 扩展欠费明细返回模型

在现有字段基础上补充：

- 入区日期 `admittedAt`
- 出区日期 `dischargedAt`
- 总费用 `totalCost`
- 预交金 `prepaidAmount`
- 医保支付 `medicalInsurancePaid`
- 个人账户支付 `personalAccountPaid`
- 最近操作人 `lastOperatedBy`

继续保留住院号、住院次数、姓名、科室、住院病区、费别、欠费类型、主管医生、原始/最终应交押金、押金差额、欠费金额、当前是否欠费、缴费状态、欠费原因、追缴进度和数据更新时间。

### 2.2 扩展列表查询

- 查询 `patient_encounter.admitted_at`、`discharged_at`。
- 返回欠费记录中的全部费用字段。
- 关联 `last_operated_by` 对应用户，返回最近操作人姓名或登录名。
- 默认按欠费金额降序、数据更新时间降序排列。
- 编辑、快捷标记缴费和恢复未缴费时写入当前用户到 `last_operated_by`，同步更新 `updated_at` 并保留统一审计日志。

## 3. 追缴状态结构化

### 3.1 状态枚举

| 编码 | 页面名称 |
|---|---|
| `NOT_STARTED` | 未催缴 |
| `NEGOTIATING` | 协商中 |
| `REFUSED` | 拒绝缴费 |
| `LEGAL_ACTION` | 移交法务发起诉讼 |
| `PAID` | 已缴费 |

实施前盘点并迁移现有自由文本；无法匹配的历史值须记录并人工确认，不得静默丢弃。

### 3.2 状态校验与联动

- 更新接口只接受合法追缴进度编码以及 `PAID`、`UNPAID` 缴费状态。
- 追缴进度为“已缴费”时，缴费状态必须为 `PAID`；其他进度对应 `UNPAID`。
- 快捷“标记缴费”同步将追缴进度设置为“已缴费”。
- “恢复未缴费”优先恢复上一次非已缴费进度；无历史状态时设置为“未催缴”。
- 联动规则由后端保证，前端仅负责交互展示。

## 4. 筛选能力

列表接口增加或完善以下参数：

```text
departmentId
arrearsType
feeType
recoveryProgress
inArrears
keyword
page
pageSize
```

页面筛选区包含：

1. 欠费类型：全部、在院患者、出院未结算、出院已结算。
2. 科室：按当前用户 DataScope 加载和校验。
3. 费别：从实际数据或费别配置接口加载，不在前端硬编码。
4. 追缴进度：使用结构化枚举。
5. 欠费状态：保留“当前欠费/未欠费”，默认“当前欠费”。
6. 关键词：支持住院号、患者姓名和主管医生模糊查询。
7. 查询和重置：重置清空筛选、恢复默认欠费状态、页码回到第 1 页，并重新加载统计和列表。

所有筛选必须在后端应用统一 DataScope，不能通过修改请求参数扩大数据范围。

## 5. 顶部统计卡片

新增 `GET /arrears/records/summary`，接受与列表相同的筛选参数并应用相同的数据权限，返回：

- 欠费患者总数
- 在院患者人数
- 出院未结算人数
- 出院已结算人数
- 欠费金额合计
- 未催缴人数
- 移交法务人数
- 最近数据更新时间

页面增加四张卡片：

1. 欠费患者数，并展示三种欠费类型人数。
2. 欠费金额合计，并展示最近数据更新时间。
3. 未催缴人数。
4. 移交法务发起诉讼人数。

统计必须基于完整筛选结果，禁止使用当前分页数据在前端汇总。查询、重置、导入成功、编辑保存、标记缴费和恢复未缴费后同时刷新统计和列表。

## 6. 欠费明细表格

表格按以下顺序展示：

1. 住院号
2. 住院次数
3. 姓名
4. 住院病区
5. 费别
6. 欠费类型
7. 主管医生
8. 入区日期
9. 出区日期
10. 总费用
11. 预交金
12. 医保支付
13. 个人账户支付
14. 应交押金
15. 欠费金额
16. 欠费原因
17. 追缴进度
18. 最近操作人
19. 数据更新时间
20. 操作

字段及展示规则：

- 住院病区优先使用 `wardName`，为空时回退到 `departmentName`。
- 应交押金使用 `finalRequiredDeposit`。
- 在院患者的医保支付和个人账户支付显示“—”；出院患者展示实际金额，零值显示 `0.00`。
- 所有金额使用千分位、两位小数并右对齐；欠费金额使用醒目颜色。
- 欠费类型、缴费状态和追缴进度统一转换为中文，页面不得直接显示后端编码。
- 追缴进度使用颜色标签：未催缴红色、协商中蓝色、拒绝缴费橙色、移交法务灰色或紫色、已缴费绿色。
- 表格支持横向滚动；固定住院号、姓名和操作列；长文本省略并支持悬浮查看。
- 保留 20、50、100、200 条分页，筛选变化后回到第 1 页。

## 7. 编辑催缴信息与操作历史

### 7.1 编辑弹窗

- 标题改为“编辑催缴信息”。
- 只读展示姓名、住院号、住院次数、住院病区和当前欠费金额。
- 可编辑字段为欠费原因和结构化追缴进度；缴费状态由后端联动。
- 欠费原因最多 500 字，保存前去除首尾空格。
- 保存期间禁止重复提交；失败时保留已输入内容。
- 表格保留“标记缴费/恢复未缴费”快捷操作，执行前展示患者姓名和欠费金额并要求确认。

### 7.2 操作历史

新增：

```http
GET /arrears/records/{id}/history
```

返回操作人、操作时间、操作类型、修改前内容、修改后内容和变更说明。编辑弹窗按时间倒序展示；无记录时显示“暂无操作历史”。保存成功后刷新列表、统计和历史。

## 8. 导入功能

- 按钮文案改为“导入欠费报表”。
- 继续仅接受 `.xlsx` 欠费导入模板。
- 导入完成后展示总数、成功、失败、新增、覆盖和跳过数量。
- 存在错误时提供进入“导入记录”的入口。
- 导入成功后页码回到第 1 页，保留当前筛选条件，并刷新统计和列表。

## 9. Excel 与 CSV 双格式导出

### 9.1 交互与接口

页面提供统一“导出”下拉按钮：

- 导出 Excel
- 导出 CSV

接口建议统一为：

```http
GET /arrears/records/export?format=xlsx
GET /arrears/records/export?format=csv
```

### 9.2 导出规则

- 两种格式使用与列表完全相同的筛选条件和 DataScope。
- 导出全部筛选结果，不受当前分页限制。
- 字段及顺序与页面一致，但不包含“操作”列。
- 两种格式使用相同的状态中文映射、金额精度和空值规则。
- CSV 使用 UTF-8 BOM 和标准 CSV 转义，避免 Excel 打开中文乱码。
- 文件名包含导出时间，例如 `欠费明细_20260901_143000.xlsx` 和 `欠费明细_20260901_143000.csv`。
- 保留现有内部全量导出上限策略；若超过安全上限，应明确报错或转为后续异步导出任务，不得静默截断。
