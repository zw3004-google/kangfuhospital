## 1. 最终确认结论

1. 页面不增加底部业务说明。
2. 欠费通报定时任务调整为每天 08:00，时区固定为 `Asia/Shanghai`。
3. 当前只支持企业微信，不提供短信渠道。
4. 一天允许多次导入；报表使用最新 `SUCCESS + READY` 欠费批次。
5. 原型“生成通报并推送”调整为只读“通报内容展示”，页面不创建推送任务。
6. 患者欠费 Top10 必须由服务端按最新成功批次、未缴费口径和当前用户 DataScope 查询，前端不得从分页列表自行计算。

## 3. 接口及权限

### 3.1 报表查询

```http
GET /api/arrears/report
```

响应包含：

- `totalAmount`、`people`
- `scopeType`、`scopeLabel`
- `latestSuccessfulBatch`
- `top3`、`ranking`
- `patientTop10`

Top10 返回排名、住院号、住院次数、姓名、住院病区、主管医生、欠费类型、欠费金额和追缴进度。金额降序后使用科室编码、住院号及住院次数稳定排序，最多返回 10 条。

### 3.2 通报内容展示

```http
GET /api/arrears/report/notice-preview
```

接口只读，复用定时企微任务的通报内容生成逻辑，返回批次、数据截至时间、范围、总额、科室分类金额、系统链接和最终文本，不创建 `push_task`。

### 3.3 通报导出

```http
GET /api/arrears/report/export
```

- 权限：`PERM_API_ARREARS_EXPORT` 或系统管理员。
- 格式：真实 `.xlsx`。
- 工作表：`报表汇总`、`科室排行`、`患者Top10`。
- 数据：与当前用户报表使用相同 DataScope、批次和未缴费口径。
- 审计：业务类型 `ARREARS_REPORT_EXPORT`，记录批次号、范围、科室数、Top10 数量和客户端 IP。

## 4. 定时企微任务

默认配置：

```yaml
app:
  messaging:
    arrears-cron: ${APP_MESSAGING_ARREARS_CRON:0 0 8 * * *}
```

- 每天 08:00 执行，`Asia/Shanghai` 时区。
- 仅面向启用且具有非空企微 ID 的科主任、主管医生。
- 继续使用企业微信发送链路，不创建短信任务。
- 数据来自最新 `SUCCESS + READY` 欠费批次。
- 数据库唯一索引及显式 `ON CONFLICT` 按提醒类型、企微 ID、日期和业务类型防止同日重复任务。

## 5. 数据模型边界

当前 `arrears_record` 保存患者最新欠费状态，并通过 `import_batch_id` 指向最近一次覆盖该患者的批次。当前实现可以保证报表各区域只读取同一个最新可用批次，但没有独立的完整历史报表快照表，因此不支持还原被后续导入覆盖前的任意历史批次。
