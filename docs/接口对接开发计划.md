# HIS 接口对接开发计划

## 1. 建设目标

在保留现有 Excel 导入能力的基础上，通过 HIS 接口实现以下三类数据的手动同步和自动同步：

1. 在院患者欠费数据同步至“欠费明细”，欠费报表基于最新明细自动汇总。
2. 出院患者欠费数据同步至“欠费明细”，欠费报表基于最新明细自动汇总。
3. 患者信息同步至“预计出院管理”，预计出院时间仍由系统内医生填报。

系统管理员可以分别配置三类数据是否启用自动同步及每日同步时间；具备权限的用户可以在业务页面手动立即同步。

## 2. 接口与业务映射

三个接口均使用以下网关：

- 请求方法：`POST`
- 接口地址：由部署环境配置，当前联调地址为 `http://172.16.101.178/wilink/api/wilink/gateway/allInOne`
- 请求时间：每次调用生成当前时间，格式为 `yyyy-MM-dd HH:mm:ss`
- 请求标识：每次调用生成唯一 UUID 作为 `MessageId`
- 机构号：由院方提供，通过环境配置维护，不在代码中写死

| 数据类型 | 交易码 | 目标模块 | 当前联调情况 |
| --- | --- | --- | --- |
| 在院患者欠费 | `BJKF_ZYCX` | 欠费明细 | 已调用成功 |
| 出院患者欠费 | `BDKF-cyqfcx` | 欠费明细 | 已调用成功 |
| 患者信息查询 | `BDKF-ZYHZXX-xcx` | 预计出院管理 | 已在可用机构配置下调用成功 |

欠费报表不是独立的数据导入目标。两个欠费接口的数据写入欠费明细后，欠费报表使用明细数据自动计算总人数、总金额、分类统计、科室排名及患者排行。

## 3. 字段映射规则

### 3.1 在院患者欠费

首期按当前接口出参完成以下字段映射：

| 接口字段 | 系统字段 | 处理规则 |
| --- | --- | --- |
| 住院号 | 住院号 | 直接写入 |
| 住院次数 | 住院次数 | 转为正整数 |
| 姓名 | 患者姓名 | 直接写入 |
| 住院病区 | 住院病区、所属科室 | 按现有科室字典匹配 |
| 费别 | 费别 | 用于欠费计算和费别系数匹配 |
| 欠费类型 | 欠费类型 | 统一转换为系统的“在院患者”类型 |
| 主管医生 | 主管医生 | 直接写入 |
| 入区日期 | 入区日期 | 转换为系统时间格式 |
| 出区日期 | 出区日期 | 在院患者通常为空 |
| 总费用(元) | 总费用 | 转换为金额 |
| 预交金(元) | 预交金 | 转换为金额 |
| 医保支付(元) | 医保支付 | 转换为金额 |
| 个人账户支付(元) | 个人账户支付 | 转换为金额 |
| 应交押金(元) | 原始应交押金 | 继续按现有费别系数计算最终应交押金和欠费金额 |

当前接口暂未返回主管医生工号，首期保存为空，不影响同步。院方后续新增工号等字段时，只扩展集中式字段映射和医生匹配逻辑，不改变整体同步流程。

### 3.2 出院患者欠费

字段结构与在院患者欠费基本一致，特殊规则如下：

- `可用预交金(元)`映射为系统“预交金”。
- 欠费类型统一转换为系统“出院未结算”类型。
- 系统“出区日期”优先使用接口的`出区日期`；为空时使用`出院日期`。
- 当前未返回的主管医生工号首期保存为空，后续按接口调整补充。

### 3.3 患者信息查询

| 接口字段 | 预计出院管理字段 | 处理规则 |
| --- | --- | --- |
| 住院号 | 住院号 | 直接写入 |
| 住院次数 | 住院次数 | 转为正整数 |
| 患者姓名 | 患者姓名 | 直接写入 |
| 性别 | 患者性别 | 直接写入 |
| 所属科室 | 所属科室 | 按现有科室字典匹配 |
| 主诊断 | 主诊断 | 直接写入 |
| 主管医生 | 主管医生 | 直接写入 |
| 工号 | 医生工号 | 用于系统用户和医生匹配 |
| 入院日期 | 入院时间 | 转换为系统时间格式 |
| 出院日期 | 实际出院时间 | 空值表示尚未出院 |
| 医保类型 | 医保类型 | 作为预计出院管理独立字段保存和展示 |

患者信息接口不提供“预计出院时间”。预计出院时间由系统内医生填报，接口同步不得新增、清空或覆盖该字段。

“医保类型”与欠费模块的“费别”属于不同模块、不同列表和不同业务字段：

- 在院、出院患者欠费接口返回“费别”，仅用于欠费明细及欠费计算。
- 患者信息接口返回“医保类型”，仅用于预计出院管理。
- 两者分别保存，不进行替代或跨模块覆盖。

接口同步不得覆盖系统内维护的预约复诊、营养会诊、居家康复、随访、特殊患者、异常原因、填报状态、欠费原因、追缴进度、缴费状态和最近操作人等业务字段。

## 4. 同步与数据一致性规则

1. 以“住院号 + 住院次数”作为同一次住院的唯一业务键。
2. 不存在的患者住院记录新增，已存在的记录按字段规则更新。
3. 每次同步根据响应中的`total`、`size`和`page`循环读取所有分页，不能只导入第一页。
4. 首期不因本次接口未返回某患者而删除、关闭或标记失效，避免接口临时遗漏导致业务数据误处理。
5. 同一数据类型同一时刻只允许一个同步任务运行，自动同步与手动同步互斥。
6. 接口同步与 Excel 导入复用相同的字段校验、科室匹配、医生匹配、费别系数、欠费计算、去重和覆盖规则。
7. 接口返回的欠费金额用于联调核对，系统展示的欠费金额仍按现有费别系数和计算口径生成。
8. 患者信息同步只更新接口负责的基础信息，不覆盖医生在系统中填报的预计出院及院后管理信息。

## 5. 分阶段实施计划

### 阶段一：接口基础能力

目标是建立可被手动和自动任务共同复用的 HIS 同步底座。

- 建立统一 HIS 网关客户端。
- 封装请求头、当前时间和唯一`MessageId`生成。
- 实现连接超时、读取超时、HTTP 状态和`AckCode`校验。
- 实现分页拉取、JSON 解析、字段转换和脱敏日志。
- 将网关地址、机构号、应用标识、超时等参数外部化配置。
- `LicId`等敏感配置通过环境变量或部署配置提供，不提交到仓库。
- 将现有 Excel 导入服务拆分为“文件解析”和“校验入库”两部分，供 API 数据直接复用。
- 扩展现有导入批次，区分`EXCEL`与`API`来源，并记录交易码、触发方式、开始/结束时间、成功/失败数量和错误摘要。
- 为患者住院信息增加独立“医保类型”字段。

### 阶段二：手动同步

目标是先完成可控的人工触发和真实数据联调。

- 在欠费明细页面增加“同步在院欠费”和“同步出院欠费”入口。
- 在预计出院管理页面增加“同步患者信息”入口。
- 增加后端手动同步接口，并配置系统管理员、运营或指定角色权限。
- 前端展示运行中状态，防止重复点击。
- 同步完成后展示批次号、总数、成功、失败、新增、覆盖和跳过数量。
- 同步失败时展示脱敏错误摘要，并可进入现有导入批次页面查看逐条错误。
- 手动同步操作写入审计日志。

建议接口形式：

```text
POST /api/integration/his-sync/INPATIENT_ARREARS/trigger
POST /api/integration/his-sync/DISCHARGED_ARREARS/trigger
POST /api/integration/his-sync/PATIENT_INFO/trigger
```

阶段一、二完成后即可在本地及测试环境使用手动接口同步完成数据验证。

### 阶段三：自动同步

- 新增接口同步配置页面。
- 三类数据分别配置启用状态和每日同步时间。
- 配置保存到数据库，修改后无需重启应用即可生效。
- 实现动态任务注册、取消、运行互斥及自动触发审计。
- 展示最近运行时间、最近成功时间、最近批次和错误摘要。
- 首期每类数据支持一个每日同步时间，后续按需要扩展多个时间点。

### 阶段四：联调、测试与上线

- 完成三个接口的成功、空数据、多页数据、异常字段、超时和业务错误测试。
- 验证重复同步、覆盖更新、并发拦截、权限、审计及批次错误详情。
- 验证欠费计算结果与现有 Excel 导入一致。
- 验证患者信息同步不覆盖预计出院时间及其他系统填报字段。
- 在测试环境完成 HIS 联调和业务验收。
- 按版本与部署规范更新`docs/RELEASE_NOTES.md`，提交并推送代码和发布说明，创建同名标签，并使用标签对应提交构建部署产物。

## 6. 权限与安全要求

- 同步配置维护与手动同步分别设置权限。
- 自动同步以系统身份执行，手动同步记录实际操作人。
- 日志和错误提示不得输出完整患者姓名、住院号及费用明细。
- 密钥、密码、患者数据和本地环境文件不得提交到 Git。
- 同步失败不得产生半批次无追踪数据；批次和错误原因必须可查询。

## 7. 测试与验收标准

1. 三个接口均可手动触发，并能完整处理多页响应。
2. 欠费接口数据正确进入欠费明细，欠费报表同步反映最新汇总结果。
3. 患者信息正确进入预计出院管理，医保类型独立保存和展示。
4. 患者信息同步不会覆盖预计出院时间及系统业务人员维护的字段。
5. 重复同步同一患者住院记录不会产生重复数据。
6. 科室、费别、金额、日期等校验错误均有批次和逐条错误记录。
7. 接口超时、网关错误及非成功`AckCode`均有明确、脱敏的失败记录。
8. 运行中的同步不能被重复触发。
9. Excel 导入功能及现有欠费、预计出院业务不受影响。
