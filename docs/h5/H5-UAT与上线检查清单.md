## 角色 UAT

每个角色至少安排 1～2 名代表，使用脱敏测试数据完成：

- □ 系统管理员：用户、科室、角色权限、费别系数、审计日志。
- □ 财务/运营：欠费查询、筛选、详情、标注和历史。
- □ 主管医生：本人患者范围、预计出院填报、异常说明。
- □ 门诊部：复诊预约、到诊和未到诊原因。
- □ 营养科：营养会诊记录。
- □ 居家康复科：居家康复记录。
- □ 随访员：第 7、30、60 天随访。

## 专项检查

- □ 360px 宽度无整页横向滚动。
- □ 横竖屏切换后筛选、弹窗和草稿仍可用。
- □ 软键盘弹出时当前输入项和底部保存按钮可访问。
- □ 浏览器返回键不造成已保存数据重复提交。
- □ 断网、15 秒超时、401、403、409 均显示明确提示。
- □ 快速重复点击保存只产生一次有效更新和审计记录。
- □ 2000 字长文本可换行、滚动、保存和回显。
- □ 切后台立即遮盖敏感内容，退出和超时清除草稿。
- □ 权限矩阵逐角色验证，直接 URL 和直接 API 调用不得越权。

## 安全门禁

- □ 正式环境设置 `SESSION_COOKIE_SECURE=true` 并仅通过可信 HTTPS 域名访问。
- □ 验证 CSP、X-Content-Type-Options、Referrer-Policy、frame-ancestors 和 Permissions-Policy。
- ☑ 本地已关闭 Basic、启用 Session CSRF 并通过自动化；详见 [整改记录](H5-CSRF与Session认证整改计划.md)。
- □ 在目标 HTTPS 环境验证 APP_ALLOWED_ORIGINS、Secure Cookie、真实浏览器跨站拦截、Session 超时和 Token 刷新。
- □ 日志不得记录密码、Cookie、企微 Secret 或完整敏感请求体。
- □ 正式环境关闭 bootstrap admin，替换默认密码和所有示例密钥。

## 灰度与回滚

- □ P0/P1 缺陷清零，核心用例 100% 通过。
- □ 业务负责人和信息科签字。
- □ 先选择少量科室灰度 3～5 个工作日。
- □ 上线前备份数据库并记录当前应用包校验和。
- □ 回滚使用上一版本应用包；本期无新增数据库迁移，应用回滚不要求结构回退。
- □ 回滚后复核登录、欠费查询、预计出院和权限范围。
- □ 扩大范围前复盘灰度期间错误率、接口耗时和用户反馈。
