# H0：H5 需求与验收基线

> 状态：本地评审稿
> 日期：2026-09-05
> 对应总计划：[`../H5访问需求评估与开发计划.md`](../H5访问需求评估与开发计划.md)

## 1. 阶段目标

H0 用于冻结一期范围、移动端信息层级、通用交互、支持终端和验收口径。本阶段不修改生产业务逻辑，不部署测试环境。

## 2. 已冻结范围

### 一期包含

- 账号密码登录、首次改密、退出、超时与无权限提示。
- 响应式应用壳层、模块式工作台和抽屉导航。
- 欠费明细查询、筛选、分页、摘要、详情、授权编辑和历史。
- 预计出院查询、筛选、摘要、详情、多角色分区填报和历史。
- 统计概览、趋势、分类切换和明细下钻。
- 推送记录只读查询。
- 用户、角色、权限、科室、费别系数和审计日志的移动端查询与维护。
- 动态水印、切后台遮盖、乐观锁、保存防重和会话内非敏感草稿。

### 一期排除

- 欠费及预计出院数据导入。
- CSV、Excel 等文件导出。
- 批量推送重试。
- 企业微信免登录、单点登录及强制企微入口。
- 角色待办首页和待办聚合接口。
- 离线提交、拍照、语音、扫码及原生 App 能力。

## 3. 访问和终端基线

- 访问范围：仅医院内网；一期允许普通手机浏览器访问，不强制企业微信入口。
- iOS：iOS 15 及以上 Safari。
- Android：Android 10 及以上、Chrome 100 及以上。
- 企业微信：医院当前统一版本及前一个主要版本，仅作为兼容浏览器，不做免登录。
- 平板：兼容约 768px 宽度。
- 不支持：IE、老旧 Android Browser、低于上述版本且不能升级的终端。

本地自动化视口：360×800、375×812、390×844、430×932、768×1024、1440×900。

真机验收最少包含：

1. 375px 左右 iPhone。
2. 390px 或 430px iPhone。
3. 360px 或 393px 主流 Android 手机。
4. 768px 左右平板。
5. 医院配发量最大的 iOS 和 Android 设备各一台。

具体型号由信息科在 H1 完成前登记，不阻塞本地开发。

## 4. 页面信息架构

| 一级模块 | 页面 | 移动端形态 | 一期操作 |
|---|---|---|---|
| 账户 | 登录、修改密码、无权限 | 单页表单 | 登录、改密、退出 |
| 工作台 | 模块入口 | 两列/单列卡片 | 进入授权模块 |
| 欠费管理 | 欠费明细 | 摘要 + 卡片列表 + 筛选抽屉 | 查询、查看、编辑、历史 |
| 欠费管理 | 通报报表 | 指标卡片 + 排名 + 明细卡片 | 查看、筛选 |
| 欠费管理 | 推送记录 | 状态卡片列表 + 详情 | 只读、单条详情 |
| 预出院 | 预计出院管理 | 摘要 + 患者卡片 + 全屏详情 | 查询、分角色填报、历史 |
| 预出院 | 统计分析 | 指标卡片 + 趋势图 + 明细卡片 | 查看、筛选、下钻 |
| 系统管理 | 用户与科室 | 分页卡片 + 全屏表单 | 新增、启停、分配角色、重置密码 |
| 系统管理 | 角色与权限 | 角色卡片 + 分组权限 | 查询、分步编辑、保存 |
| 系统管理 | 费别系数 | 版本卡片 + 全屏表单 | 新增版本、启停 |
| 系统管理 | 审计日志 | 搜索 + 日志卡片 + 详情 | 查询、查看 |

导入记录入口可保留只读，但不得显示“发起导入”；所有导出和批量重试按钮在 H5 一期隐藏。

## 5. 核心页面字段优先级

### 欠费卡片

首屏字段：患者姓名、住院号/住院次数、科室、主管医生、欠费金额、欠费类型、追缴状态。

详情字段：性别、费别、应交押金、预交金、欠费原因、备注、导入批次和操作历史。编辑入口由权限决定。

### 预计出院卡片

首屏字段：患者姓名、住院号/住院次数、科室、主管医生、预计出院时间、实际出院时间、状态、异常标识。

详情按职责分区：患者摘要、主管医生、门诊部、营养科、居家康复科、随访、操作历史。无权限区只读或隐藏编辑控件，最终以现有后端字段权限为准。

### 系统管理卡片

- 用户：姓名、工号、登录名、科室、角色、状态；高风险操作收纳至“更多”。
- 科室：编码、名称、状态。
- 角色：名称、编码、启用状态、权限摘要、科室范围摘要。
- 费别系数：编码、名称、系数、状态、生效时间。
- 审计日志：时间、操作人、模块、动作、业务对象；前后值进入详情。

## 6. 通用交互基线

- 小于 768px 使用移动壳层：顶部栏、抽屉菜单、内容单列；桌面左侧栏不显示。
- 页面不得产生整页横向滚动。经设计确认的复杂矩阵可在自身容器内横向滚动。
- 触控目标不小于 44×44px；正文不小于 14px。
- 列表默认 20 条/页，手机使用“加载更多”或简化分页。
- 常用关键词搜索外露，其他筛选项进入底部/侧边筛选抽屉，并显示已选数量。
- 手机详情和编辑使用全屏页面或全屏抽屉；表单改为单列，底部提供吸附保存栏。
- 保存期间禁用重复提交；失败保留已输入内容并提供重试。
- 浏览器后退优先关闭弹层，再返回列表；从列表返回时保留非敏感筛选和滚动位置。
- 空数据、无权限、网络失败、登录超时和并发冲突使用不同提示，不得统一显示“请求失败”。

## 7. 安全与数据一致性基线

- H5 延续后端菜单、接口、数据范围和字段权限，不能仅靠隐藏按钮控制权限。
- 页面显示当前登录人和时间的低干扰动态水印。
- 页面进入后台时遮盖业务内容，返回前台恢复；空闲 30 分钟重新登录。
- H5 不承诺阻止系统截屏；通过水印、审计和院内制度追责。
- 不全局禁用复制；身份证号、电话等高敏感字段如后续展示，应单独限制。
- 业务更新采用乐观锁。冲突时返回明确的冲突错误，不自动覆盖他人修改。
- 草稿仅保存非敏感编辑内容并限定当前登录会话；提交成功、退出、超时或切换用户时清除。
- 当前 `sessionStorage` Basic 凭据方案应在 H1 调整为服务端会话或安全 Cookie，H0 不改认证代码。

## 8. 角色验收矩阵

| 角色/职责 | 数据范围 | 一期核心验收 |
|---|---|---|
| 系统管理员 | 全部 | 全模块访问、系统管理维护、审计可见 |
| 运营部 | 全部业务数据 | 欠费与出院查询、授权编辑、统计查看 |
| 财务科 | 全部欠费相关数据 | 欠费查询、授权编辑、通报查看 |
| 科主任 | 所属科室 | 不得看到其他科室，授权操作有效 |
| 主管医生 | 本人患者 | 不得看到其他医生患者，主管医生字段可编辑 |
| 门诊部 | 后端授权范围 | 仅可编辑门诊预约与到诊字段 |
| 营养科 | 后端授权范围 | 仅可维护营养会诊信息 |
| 居家康复科 | 后端授权范围 | 仅可维护居家康复信息 |
| 随访员 | 后端授权范围 | 仅可维护随访字段 |

## 9. H0 验收用例

1. 原型在 360px 宽度无整页横向滚动。
2. 抽屉菜单可打开、选择模块并关闭。
3. 工作台只展示模块入口，不展示角色待办。
4. 欠费卡片包含首屏优先字段，详情包含次级字段和历史入口。
5. 预计出院详情按职责分区，移动表单为单列。
6. 系统管理包含用户、角色、权限、科室、费别系数和审计入口。
7. 原型不提供导入、导出和批量重试操作。
8. 原型展示水印、切后台遮盖、并发冲突和草稿规则说明。
9. 375px、390px、768px 和桌面视口均能阅读和操作。
10. 业务方确认核心卡片首屏字段，信息科确认终端和安全口径。

## 10. H0 退出与 H1 启动条件

以下交付物齐备即可进入 H1：

- 本需求与验收基线。
- 本地低保真交互原型 `h0-mobile-prototype.html`。
- 总体 H5 需求评估与开发计划。
- 已确认的一期范围、排除项、终端建议和安全策略。

不阻塞 H1 基础框架开发、但应在 H1 结束前补齐：

- 业务负责人、信息科负责人及各角色 UAT 代表名单。
- 医院实际主流测试机型清单。
- 关键卡片字段和系统管理移动流程的原型签署意见。
- 内网 HTTPS 域名和移动终端证书信任方案。
