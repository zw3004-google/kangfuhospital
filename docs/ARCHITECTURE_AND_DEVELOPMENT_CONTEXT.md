## 1. 系统范围

系统分为三个业务模块：

- 欠费管理：欠费明细、通报报表、推送记录。
- 预出院管理：预计出院管理、统计分析。
- 系统管理：费别系数、用户管理、角色/权限、科室管理、审计日志。

主要业务量：

- 欠费、预出院每天单次导入不超过 1000 条。
- 每天约 50 次重复导入，重复患者覆盖业务字段但保留人工标注。
- 并发登录用户不超过 100。
- 每天导出约 15 人次。
- 企微每日推送总量不超过 1000 条。
- 系统为医院内网访问，需要访问企微接口。

## 2. 已确认业务规则

### 数据覆盖

患者唯一性不能只使用住院号，建议使用：

```
住院号 + 住院次数
```

否则同一患者多次住院可能发生串数据。患者与主管医生按工号关联，同时保留导入的医生姓名用于展示和核对。

### 欠费金额

应交押金由接口或导入数据获取后乘费别系数展示：

```
最终应交押金 = 原始应交押金 × 费别系数
欠费金额 = 最终应交押金 - 预交金
```

是否取零由最终业务规则确认；如要求欠费金额不出现负数，使用：

```
max(最终应交押金 - 预交金, 0)
```

### 主管医生与科室

- 一个医生只属于一个科室。
- 用户角色不放在用户导入表中，导入后由管理员分配。
- 用户以企微 ID 作为唯一识别码。
- 主管医生按工号精确匹配唯一启用用户，并保存用户 ID、原始工号、原始姓名和匹配状态。
- 科主任和主管医生通过角色分配识别，不额外增加“是否科主任”字段。

## 5. 权限模型

### 数据范围

`DataScope` 统一用于列表、导出和修改：

- 系统管理员：全部数据。
- 运营部：全部数据。
- 财务科：全部数据。
- 科主任：所属科室数据。
- 主管医生：`doctor_user_id` 等于当前登录用户 ID 的数据；未唯一匹配的数据不进入主管医生个人范围。

修改 SQL 必须带同样的数据范围条件；影响行数为 0 时抛出 `AccessDeniedException`。

### 字段权限

代码中已设计字段权限服务，主要编码：

- `FIELD_ARREARS_REASON`
- `FIELD_RECOVERY_PROGRESS`
- `FIELD_FOLLOW_UP`
- 预出院营养、居家康复、护理、主管医生字段权限

阶段 0 已确认第一期不实施细粒度字段编辑限制：所有登录用户可编辑其 DataScope 内可见患者。阶段 2 已移除业务更新接口中的 `FIELD_*` 强制校验；上述编码仅保留为后续扩展能力。

### 页面权限

- 菜单无权限自动隐藏。
- 按钮按权限编码控制。
- 直接访问无权限路由拦截。
- 未登录跳转登录页。
- 401 自动退出或重新登录。
- 403 显示无权限页面。

## 12A. 后续开发前需补齐的项目资料（历史记录）

### 12.1 数据字典

需要由项目方最终确认以下内容：

- 患者唯一标识：住院号 + 住院次数，或医院现有业务主键。
- 主管医生关联字段：工号字段名称、数据格式和是否允许为空（关联方式已确认为按工号匹配）。

- 欠费金额相关字段：应交押金、费别系数、预交金、欠费金额。
- 预出院日期字段：仅日期和带具体时刻的日期分别如何处理。
- 所有金额、日期、状态字段的精度、时区和允许空值规则。

### 12.2 角色权限矩阵

开发和验收前应形成正式矩阵，至少包含：

| 角色 | 菜单范围 | 查询范围 | 修改范围 | 导出范围 | 字段权限 |
|---|---|---|---|---|---|
| 系统管理员 | 全部 | 全部 | 全部 | 全部 | 全部 |
| 运营部 | 业务菜单 | 全部 | 按业务授权 | 全部 | 按业务授权 |
| 财务科 | 欠费相关 | 全部 | 按业务授权 | 全部 | 欠费字段 |
| 科主任 | 本科室业务 | 本科室 | 本科室 | 本科室 | 业务字段 |
| 主管医生 | 预出院/随访 | 本人患者 | 本人患者 | 本人患者 | 主管医生字段 |

正式角色编码必须与数据库中的 `sys_role.role_code` 一致。

### 12.3 接口约定

每个接口应补齐以下信息：

- URL、HTTP 方法和权限编码。
- 请求参数、分页参数和排序规则。
- 成功返回结构和错误返回结构。
- 401、403、409、422、500 的处理约定。
- 导入接口的错误行返回格式。
- 导出接口的最大记录数和超时策略。

统一建议：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 12.4 导入模板与校验

每个导入模板需要明确：

- 文件格式：xlsx 或 csv。
- 表头名称和字段顺序。
- 必填字段、长度、日期和金额格式。
- 重复记录的覆盖键。
- 人工标注字段是否保留。
- 错误行是否全部回滚，还是成功行继续导入。
- 导入结果是否返回新增、覆盖、跳过和失败数量。

建议导入采用“单批次事务 + 错误行报告”，未经确认不覆盖人工标注字段。

### 12.5 企微配置

上线前需要提供：

- Corp ID、Agent ID、Secret 的正式来源。
- 接收人通过企微 ID、工号还是部门匹配。
- 科主任和主管医生的接收人规则。
- 推送时间、消息模板和失败重试次数。
- 企微 API 出口、代理、DNS 和证书要求。

Secret 不写入代码仓库，应通过环境变量或部署服务器密钥文件注入。

### 12.6 统计分析口径

统计分析专项批次 1～7 已实现，详细记录见 [统计分析页面差异与修改计划](统计分析页面差异与修改计划.md#11-实施结果2026-09-03)。当前规则如下：

- 月度指标按实际出院时间归属，使用 `encounter_id` 对一次住院去重，时间边界统一采用 `Asia/Shanghai`。
- 非计划出院包含计划缺失或预计与实际出院日期不一致；营养、居家、复诊分子均为当月实际出院患者中的有效预约人数。
- 每日趋势为当月 1 日至当天的累计值，四类比率分母均为累计实际出院人数；分母为 0 时返回 `null`。
- 指标、趋势、六类明细、导出和下钻复用统一筛选条件与 `DataScope`，前端条件只能缩小、不能扩大后端权限范围。
- 正式导出优先 XLSX、兼容 CSV，同步上限 20,000 条；导出和人工提醒触发写入审计日志。
- 人工提醒覆盖营养、居家、7/30/60 天随访和非计划出院，并通过任务唯一键保证同日同接收人同类型幂等。
