# 阶段 2：权限与安全闭环

> 执行日期：2026-08-31  
> 状态：`VERIFIED`——五类角色的数据范围、查询、修改、导出、统计及越权拒绝已通过 PostgreSQL 集成测试。
>
> 阶段 3 已于 2026-08-31 验证完成，当前基线参见 [`../phase3/README.md`](../phase3/README.md)。

## 1. 已完成

- 新增 Flyway V10，为系统管理员以外的业务角色建立明确的操作权限映射。
- 修正 Spring Security HTTP 方法匹配，导出权限在通用查询权限之前独立校验。
- 修正数据库用户角色与权限加载，避免角色覆盖 `PERM_*` 权限。
- `DataScope` 支持多角色范围并集：全院、角色科室和主管医生本人患者可同时合并。
- 科主任范围来自 `sys_role_department`；主管医生范围使用 `doctor_user_id`，不再依赖姓名或展示字段。
- 欠费与预出院查询、修改、导出复用相同范围条件。
- 欠费报表、预出院统计和会诊预约接口统一应用 `DataScope`。
- 移除一期细粒度字段编辑限制；登录用户可编辑其数据范围内可见患者。
- 预出院导入仅允许系统管理员和运营部，主管医生调用返回 403。
- 业务层越权统一返回 403，不再被兜底处理为 500。
- 修正预出院更新字段名和欠费更新 SQL 中的存量错误。

## 2. 自动化验收范围

PostgreSQL 集成测试覆盖：

- 系统管理员、运营部、财务科全院查询；
- 科主任仅访问配置科室；
- 主管医生仅访问 `doctor_user_id` 为本人的患者；
- 欠费与预出院列表、修改、CSV 导出；
- 欠费报表和预出院统计的数据范围；
- 跨科室、跨医生修改返回 403；
- 主管医生调用预出院导入返回 403；
- Flyway V1～V10、管理员初始化和固定测试数据。

最终完整验收结果：后端 19 个测试，0 失败、0 错误、0 跳过；前端 TypeScript 检查和 Vite 生产构建通过。
